# Autonomous decisions

`autonomy_mode=Autonomous` delegates routine implementation, missing minor UI states, scoped technical repairs and normal Git recovery. Reuse recorded human authorization and valid checks. Do not ask whether to continue or fix an error. A failed test is repair work; only a concrete external dependency makes it Blocked. Search/reuse a minimal prerequisite task when actual support is missing, then let native dependency ordering select it. Never claim external approval is pending without a real request.

Screenshots and playthroughs are primarily agent verification. Compare relevant actual outputs yourself, fix material differences and reuse unchanged verified evidence. Do not send every screenshot for approval, presume current UI is wrong, invent fidelity percentages, or re-audit unchanged screens. Consult the human only for indispensable information, conflicting human requirements, actual inaccessible resources, a specific irreducible visual preference or a real human playtest. Do not fabricate a physical sample or human review.

For a necessary question, CLI `ask --input question.json` accepts `question`, `question_category` (`missing_input`, `conflicting_requirements`, `visual_review`, `playtest`, `access`), `human_requirement` (20..600 characters explaining exactly why the agent cannot decide), at least two concrete `options`, and optional concise `continuity`. Attach the relevant screenshot/report to this task when useful. MCP uses the same `agent_interaction(action=request,kind=question,...)` payload. The ask_human helper accepts `--question-category` and `--human-requirement` for the same operation.

Autonomous questions return `deferred=true`: the native engine parks only this task as a human blocker, releases its task/file/batch reservations and preserves the callback for seven days with a requirement-scope fingerprint. Exit this run, do not wait/poll/finish the task. The next normal supervisor launch preserves its edited files under the configured checkpoint policy and takes other eligible work. A human answer reopens the same task with saved continuity and input, subject to dependencies, Stop, quota and provider authorization. No model is started merely to check for an answer. A changed scope or cancelled/completed task invalidates the old question. Permission callbacks remain separate, live, one-shot and human-only; this mode never approves a rejected command or changes sandbox policy.
