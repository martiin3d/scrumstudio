# Efficient checks for large generated/imported sets

For large generated/imported sets, run deterministic import/hash/manifest/binding assertions locally once and read counts/exceptions plus a report path. Do not dump binary/base64, font/prefab YAML, whole manifests or successful per-file reports. `task_get` preserves execution criteria/continuity but pages large file plans (20 paths by default); use `files_after`/`files_limit` only for needed pages, or explicitly `full=true` for the whole plan. Never replace the saved file plan with a partial page.

Visual review uses family/variant samples and every explicit acceptance or changed-layout risk. Default target: six representative captures; exceed it when distinct variants, failures or mandatory criteria require coverage. Reuse already inspected unchanged captures; do not repeat the whole review at closure. Automated structural/binding assertions still cover every generated output. The supplied `scripts/work_checks.py` offers `files` (array of path/optional sha256) and `visual` (array of id/family/variant with optional required/changed_risk) with `--input`, `--report` and files `--root`; it prints a compact summary and saves full details. A plan or hash pass never certifies visual/functional acceptance.

Managed workers receive at most one native `efficiency_notice` per run when configured elapsed/tool/output thresholds are reached. Accommodate it in the next necessary update: preserve a concise finding and next step, stop duplicate exploration and finish the smallest remaining acceptance. It adds no auditor model or polling and does not authorize skipping checks, creating speculative tasks, blocking, exiting or relaunching solely because of cost. Live tokens may be unavailable until the provider finishes; never infer them from tool counts/time.

Git completion fingerprints are computed in one native batch with repository filters; commit checks use bounded path chunks. Do not replace a failed completion receipt with a success claim. At an idle launch boundary, native Git may repair false dirty index metadata only when the full staged blob/mode/stage listing stays identical. Real edits, existing staging, index locks, conflicts and unverified changes remain protected; they are not permission to reset/stash/discard or mark Done.


For a visual change, optional native `scripts/visual_compare.py --reference REF --actual CAPTURE --output DIRECTORY` emits a cached overlay, raw diff and compact report for matching dimensions. It does not stretch inputs, call a model, assert semantic fidelity or request human approval. Reuse only when the source design version and actual output inputs remain valid. Inspect/fix material differences yourself; captures are not a reason to consult the human routinely.

Temporary test session stores, scratch exports and interaction records belong in ignored Logs or .scrum/local scratch locations, distinct from deliverable screenshots/PDFs. If legacy tests create them under versioned Artifacts, use narrow fixture-specific ignores after verifying provenance; never ignore all Artifacts. Inspect test-generated tracked cache edits before closing. Preserve existing user edits and do not repeat rejected recursive cleanup. Scoped Git recovery can use the native private-retention helper described in lifecycle.md; it preserves bytes without publicizing unknown edits.
