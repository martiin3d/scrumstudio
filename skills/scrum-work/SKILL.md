---
name: scrum-work
description: Execute or resume Scrum Studio tasks with claimed scope, native continuation and concise task continuity.
---

When the supervisor selects native CLI coordination, use its supplied `scrum.py` command and inherited private context instead of Scrum MCP. Read [CLI commands](references/cli.md) only as needed. The operations below describe workflow semantics; invoke them through the selected channel. Do not inspect claim context files or print tokens. Other specialist MCP servers remain available.

When `autonomy_mode=Autonomous`, resolve routine implementation/recovery/design choices yourself. Read [autonomous decisions](references/autonomous-decisions.md) only for a genuinely indispensable human question. Screenshots are internal verification, not routine consultation. Do not infer defects or redo valid work.

For a managed worker, the supervisor supplies the current task, fresh claim token and Git diagnostics. **Use that scope directly**: no work_start, task_claim, task_get, settings/quota probe, board scan or planning pass at startup. Fetch linked agent notes only when pending_ai_notes>0. If preserved_inputs is supplied, use its checksum-verified read-only copies when a required draft is absent from Git/the checkout; inputs_after/inputs_limit page the references. Do not declare those inputs lost or restore another branch. Copies remain unfinished source material, not acceptance evidence. A file plan page is not the complete plan; never overwrite it with a partial page.

For interactive work without a supervisor claim, discover the project by checkout, use work_start once and resume your own unfinished work first. Read [full lifecycle](references/lifecycle.md) for discovery, exceptional closure/recovery or administrative details; managed ordinary execution does not need it.

1. **Execute the current outcome.** Inspect relevant source and pre-existing edits and reuse saved findings/checks. With claim file_lock_mode=checkout, the task lease provides exclusive checkout ownership: skip per-file lock calls and declare only your additional output/support files (including Unity .meta sidecars) via additional_files in the existing work_finish call, or CLI finish --paths FILES. Otherwise acquire file_locks for extra outputs before editing. Keep explicit commit scope; never adopt pre-existing/unrelated dirty paths. Existing dirty paths do not establish authorship. Read only missing relevant source; do not repeat unchanged diffs or broad exploration. Follow the installed codebase-memory skill for structural queries; verify coverage and use source fallback when unavailable/stale. After a transport failure, stop graph retries for this run and reuse bounded source findings; do not re-index the repository for one question.
2. **Verify proportionally.** One targeted check for each changed behavior plus explicit acceptance. Reuse an unchanged passing report with its original time. Broaden only for shared behavior, failures or unresolved risk; no per-task full-suite or separate review essay by default. Never skip required acceptance. Use native helpers supplied by the supervisor for tests, hash/import checks and visual sampling; read counts/exceptions, not complete successful logs. Visual inspection covers explicit cases, distinct families and changed-layout risks; a compile pass is not visual proof. Large imports/visual sets: [efficient checks](references/efficient-checks.md). Tool failures require a changed hypothesis and bounded authorized repair, never an unchanged retry loop.
3. **Close and continue.** work_finish(id,token,evidence,client,use_batch=true,claim_next=true) completes only verified work, integrates under enabled Git policy, and may return next.task plus next.claim. A successful returned claim already grants its token and full scope: continue directly in this CLI, without rediscovery/reclaim/rereading unchanged context. Finish each outcome separately; reserved future tasks remain TODO. Stop when batch_done, should_stop, session offline, a real impediment or no successful next claim. Never select outside the reserved batch. With no batch, use work_finish(close_session=true,client=...). Failed/uncertain completion is not permission to repeat a write: reconcile the recorded state through show/status in the selected channel; pause for supervisor reconciliation when a CLI write is uncertain.
4. **Continuity only when useful.** For small work, no intermediate update; put only new verification facts in completion. For a costly finding or real interruption, one task_update with concise `Done: ...; Next: ...` and relevant paths/report. No duplicate chat/work log/review/handoff essays, routine metrics or human-only notes in agent context. Do not record long successful command output. Native checkpoints preserve edits automatically.
5. **A real blocker is distinct from failed work.** Diagnose and fix scoped errors, missing references and blank captures before blocking. Blocked requires an unmet prerequisite or external constraint plus the exact next action. Link existing dependency tasks; mark dependency-only prose blocked_reason_kind=dependency so native completion can clear it. Keep acceptance unverified until it passes. With human-enabled agent_followup_tasks, search/reuse and register only the minimum concrete prerequisite through task_plan; use task_plan(defer_task=current ID, prerequisites=[plan keys or existing IDs], items=[minimum concrete outcomes], continuity=concise findings) with the current token (CLI injects it). This atomically links prerequisites, parks only the current task and releases its claim/batch while preserving acceptance/evidence. On deferred=true exit so the supervisor selects ready work. Do not include the claimed task as a refinement item. A PLAN_REJECTED response proves rollback: correct the plan in the same run; uncertain transport writes still require reconciliation. Human/physical review cannot be self-certified. No speculative backlog or routine replanning.

Stop, quota, dependencies, WIP, model overrides, real permissions and others' reservations remain authoritative. Quota is supervised outside the model: no provider probes or periodic AI checks. An efficiency_notice is advisory, never permission to exit/relaunch, weaken acceptance or create a task solely for cost. Reuse human authorization already granted; request actual reviewed tool escalation for a sandbox access failure, never invent pending approval or bypass rejection. For an installed Unity test helper reporting environment_access, submit the real reviewed retry of that command in this turn; diagnose the newest complete log and require an executed/passing machine-readable report. Do not alter licenses/accounts. For genuine human decisions use request_user_input or the supplied ask_human helper, waiting for the actual answer.

Git is native under enabled policy: no manual branch switching/stash/reset/publication in an ordinary task. Read [full lifecycle](references/lifecycle.md) only for scoped Git recovery, worktrees or unresolved publication; preserve unrelated/partial work and staging, never force push. Do not mark Done from commit/exit success alone. Evidence must match verified inputs and successful required integration. Future tasks in the same group are reserved, not simultaneously claimed; a fresh next claim rechecks urgency, dependencies, files, model, Stop and quota.


An unspecified reference state is not automatically a human-approval requirement. When the authorized task permits routine implementation decisions, record an explicit minimal choice consistent with the existing UI and distinguish it from Figma-certified coverage. Ask only when the project actually reserves that decision for the human or the choice materially changes scope. Never fabricate human/physical review. Native launch repair can replace legacy directory placeholders in your idle task file plans with bounded explicit Git-visible leaves; new reservations should name exact output files.

Intentional decisions: when an authorized outcome introduces or changes a lasting design/behavior choice, add only the relevant decision(s) to the existing work_finish call (CLI finish --decisions-file JSON_ARRAY_FILE, or finish --input with decisions). Each entry: key (stable lowercase slug), decision (max600 chars), reason (max300), files (relative exact paths or directory/** scopes), optional supersedes (the ref values of current same-key records). Do not generate records for every task, routine fixes, logs or human-only summaries. Source task links/history are automatic; only Done outcomes become current. In Review/Blocked records remain proposed. Existing task_get/preclaim automatically includes decision_context for matching planned files only; preserve those choices during implementation/audits, do not revert them just to match an older reference. A newer explicit human requirement can supersede a decision; name the prior refs explicitly. Conflicting keys require reconciliation, not silent replacement. Read has_more pages via decisions_after/decisions_limit before changing covered behavior; decision_files can target newly discovered exact paths or directory/** without scanning the board. No unrelated decision history, periodic AI audit or extra close call is required. Screens/components are scoped through their actual source files; explain any authorized departure from old design references in the reason. File-less tasks receive no global decision dump.
