---
name: scrum-work
description: Execute Scrum Studio board tasks in this checkout - start/resume, plan, claim, verify, finish or hand off - with minimal tokens and no repeated work.
---

Self-contained lifecycle. Load another scrum-* skill only for its specific operation.

1. **Start** once per session: `work_start(project, client, actor | identity+name)`. If the context already has a "Scrum Studio board (loaded by hook" block or the supervisor says it claimed the task, skip this discovery call and use what it gives. Find the project with `projects` by checkout folder; reuse your persistent identity. Cache `settings_version`, task versions and `measurement_session`; pass `settings_seen`/`task_seen` so unchanged data is omitted. `should_stop=true` → stop.
2. **Resume first.** `resume` lists your own unfinished tasks with their continuity; `next_work` also returns them first. Continue them (`task_get`, then claim) before planning or starting anything else. Keep recorded checks; redo only what continuity or changed files invalidate.
3. **Plan only new authorized scope** ([scrum-rules](../scrum-rules/SKILL.md)): `task_search` first, then one `task_plan`. A same-title unfinished task comes back `existing=true` and nothing is created: continue it rather than creating a copy; an identical Done outcome is already delivered, while changed scope on Done creates new work. `differs=[...]` lists what changed between your plan and the registered task (wording, criteria, files): if the scope really changed, refine that task with `task_plan(items=[{id, ...}])`; a mere rewording is the same work. `allow_duplicate=true` only for a deliberately separate outcome. A backlog-only request never authorizes execution.
4. **Start and claim in one call** when you already know the task: `work_start(id, claim=true)` (add `files` only to change the planned set). It applies the same atomic checks as `task_claim` (dependencies, WIP, file conflicts); use `task_claim` only after `claim_deferred` or `claimed=false`, or to claim the next task later in the session. Only `claimed=true` grants the token. Respect WIP, dependencies and other agents' file reservations ([scrum-file-locks](../scrum-file-locks/SKILL.md) only on conflict). Never reuse another worker's identity or recover a lost token with a new one.
   `claimed=false` with `branch_busy` (project git automation on): the checkout still holds uncommitted work of another branch; do not stash, revert or switch branches yourself. Finish or hand off your own task on that branch if it is yours, otherwise call `next_work` again (it already filters by the checkout's branch; `branch_skipped` says how many tasks were held back) or use `exclude_ids=[id]`; the refusal is already recorded on the task. A `git` field on a successful claim (`created`/`switched` branch, or `error`) is informational: the server applies the human-enabled Git policy; report failures without silently switching branches or retrying a publication.
   Before editing, inspect the relevant files and existing edits. `dirty_planned` identifies pre-existing changes, including your own interrupted work; it does not establish authorship. Use an existing diff or `task_changes(id, files=[...])` when needed; do not reread unchanged files or create a mandatory assessment log.
5. **Save progress sparingly:** Stop/quota handoffs and crashes already record the edited files automatically (from git, no model call), so:
   - Small task: no intermediate saves; put `continuity="Done: …; Next: …"` in the call you already make (`work_finish`, or one `task_update` before a deliberate pause).
   - Long task, or right after a costly finding (root cause located, design decision, non-obvious constraint): one `task_update(continuity=…)` with the finding and the next step. One call per real milestone, never per step; it replaces the previous summary.
   - On resume, an `interrupted=true` item lists its `edits`: `task_changes(id)` shows that diff in one call; inspect it before continuing.
6. **Verify proportionally:** `scripts/verify.py --files PATH... --run --reuse`. Evidence = checks actually run.
   Reuse human authorization already granted for installed project tools. Request genuinely additional permissions through the normal tool/reviewer; never claim approval is pending without an actual request. For a recoverable tool error, inspect its cause and attempt a bounded repair within existing authorization before exiting; request minimal real tool escalation for access errors. If installed Unity cannot access its per-user configuration/licensing helper in the sandbox, request normal reviewed execution of that specific test command; do not change licensing or broaden AppData access. Submit that real reviewed retry in the same turn; deferring the request in continuity is not recovery. Inspect the newest complete log: later compiler errors take priority over earlier licensing reconnect warnings. After bounded repair and an actual reviewed failure, mark a genuine impediment Blocked, close safely and let the supervisor take other eligible work. Never repeat an unchanged failing launch. Required tests need a fresh machine-readable report showing executed tests and passing results, not just exit code 0. Keep tasks unfinished when their acceptance remains unverified. Surface real permission blockers in task continuity and Chat; preserve reviewer rejections.
   Failed verification is repair work, not by itself a blocker. Fix scoped code, missing asset/font references and capture setup in this task. Bound retries per hypothesis: inspect the actual failure, change the cause or diagnostic, then run the smallest relevant check; do not repeat an unchanged launch. A retry count alone never establishes an external impediment. Use Blocked only for a concrete unmet prerequisite or external constraint, recording attempted repair and the action needed to resume. Prefer dependency links alone; accompanying dependency-only prose requires `blocked_reason_kind=dependency` so it clears automatically, while a separate constraint uses `external`. If repair is still possible but the session must end, save precise continuity and release as TODO; respect Stop/quota. For Unity blank renders, inspect the assigned font, Canvas/camera, graphics mode and frame/layout timing before blaming the environment. Preserve visual acceptance; compilation alone is not visual proof.

   Review changes proportionally to risk. Reuse a diff already inspected; request `task_changes` only when it adds missing evidence, especially after an interruption or unexpected edits. Its output enters model context; local diff generation does not make reading it token-free. On `truncated=true`, inspect the relevant subset rather than requesting the same dump. A small mechanical change needs no separate review essay. Record only material findings, remaining risks or continuation information.
7. **Finish:** `work_finish(id, token, evidence, log?)` with an optional concise `log` only for new relevant findings; with git automation on, the response's `git`/`git_push` report the server-side commit and push (or their failure) — relay a failure to the human, never retry git yourself; add `claim_next=true` to claim and load the next task in the same call (its token is in `next.claim`), so chaining costs one call per task; `already_done=true` on a retry means complete, never redo it. Use In Review for pending human approval, Blocked for impediments.
8. **Quota/Stop:** supervised by the bridge in Wakeup runs. Optional Claude hooks check at prompts/response/session boundaries, not during long tool sequences; use safe-boundary checkpoints during long unsupervised work. Otherwise [scrum-usage](../scrum-usage/SKILL.md) at safe boundaries. Stop editing before `agent_checkpoint(action=pause|offline)`; it saves continuity and releases your work.
9. **End:** [scrum-close](../scrum-close/SKILL.md).

Token rules: `next_work`, `task_search` and batch headers are navigation; load `task_get` before editing. `task_changes` is on demand, default 200 diff lines; narrow with `files` rather than raising `max_lines`. Fetch snapshots, history, metrics, costs, notes or attachments only when needed (`pending_ai_notes>0` → `task_get(include_notes=true, notes_content=true)`). No routine chat, Daily, Retrospective or duplicate logs. Rare topics (managed batches, model routing, MCP transport recovery, graph-first code reading): [core guidance](references/core-guidance.md).

Git recovery exception: a task whose category is `Git recovery` authorizes its scoped integration/merge and normal push. Inspect current refs and recorded branch parents, plan/reserve files before editing, preserve other work and staging, and never force push. A completed prerequisite may need its verified commits integrated before an unfinished context group closes; that does not complete its remaining tasks. Reconcile related completed prerequisite branches in the same recovery when safely independent, reusing valid verification; never merge unfinished edits or redo implementation. For nested branches, follow each recorded parent in order; before propagating an intermediate tip, verify its additional commits belong to completed, verified work. Stop at an unfinished or uncertain intermediate outcome and record the exact boundary rather than skipping parents. A retained branch name alone is not pending integration: check commit ancestry and the remote publication. Verify ancestry/publication before completing recovery. Only a concrete external constraint justifies blocking; save the exact remaining action and let the supervisor take other eligible work. Ordinary tasks leave enabled Git automation to the server.

With Git Worktrees mode, the supervisor starts you in the task workspace from claim.git.worktree. Keep the canonical project ID and central board; never register a separate board for the worktree. Edit only the assigned workspace and use relative file plans. On any later claim, honor its worktree path before editing. Other task/context workspaces have independent branches/indexes; central file reservations still apply. Preserve partial edits; workspaces remain available across sessions.

Human-only project_settings(git_cleanup=true|false), default false: after successful integration, queue removal of the local branch and clean managed worktree, executed by the existing supervisor offline checkpoint after CLI exit. No AI turn or polling is added. Remote branches, dirty/ignored files, checked-out unmanaged branches and branches needed as origins are retained. Do not manually delete active or unfinished workspaces. Cleanup skips are reported separately from merge failure and never launch a recovery model.

Before cleanup, native code rechecks the task dependency/context component and defers while any related task is not Done/Cancelled, including newly added work. Deferred candidates are reconsidered at later existing CLI-exit events, without polling or model turns. Prefer Branches for one worker when the canonical checkout can be used safely; Worktrees provides optional isolation for parallel workers or a human checkout. Never migrate active/saved workspaces automatically when worker count changes.

Git recovery tasks use the existing checkout and may preserve dirty files/staging; they remain eligible when no other live claim needs the checkout. Never bypass active claims. For direct MCP CLI fallback omit --timeout to use operation-specific bounds (15 seconds ordinary calls, 180 completion writes); never retry an uncertain write without reconciling recorded state.

Human decisions: use request_user_input when available; otherwise the supervisor-supplied scripts/ask_human.py helper shows project Chat options and waits locally. Never invent approval, poll a model for answers, or send secrets. Auto review still requires a real reviewed tool request and cannot override a denial.

Codex project permission modes: `Auto review` reviews sandbox escalation requests; `Ask in chat` routes real requests to human buttons; human-selected `Full access` launches workers without local sandbox restrictions or permission prompts. Full access does not override organization/OS restrictions, Stop, quota policy, task dependencies or reservations. Do not change a project to Full access without explicit human authorization. If a blocked task leaves dirty files on its branch, preserve them: do not stash, discard or commit unrelated edits to switch branches. Use isolated Worktrees when authorized, or report the checkout blocker with the saved continuity. Only checked prerequisites count; Done prerequisites permit execution.

For automatic closure recovery, resume the existing task's edits and remaining verification/Git closure. Inspect saved reports and their inputs before rerunning checks; do not repeat unchanged verified work. Complete or hand off through the normal task workflow before exiting: a successful CLI exit alone does not complete a task. Subagents return results to the owning agent; the owning agent remains responsible for task completion/publication.

Autonomous follow-up: when the human-authorized outcome encounters a concrete prerequisite or recovery need, search existing work and use task_plan to register/refine the minimum necessary tasks with acceptance criteria and actual dependencies. No separate permission is needed for this planning within the authorized scope. Save/release the current task before executing another; the supervisor chooses eligible work. Never create speculative backlog or run planning on every task. Required checks that fail keep the task unfinished even when implementation is committed; repair within scope and reserve Blocked for the impediments defined above. Unity-generated .meta files belonging to your outputs and new folders are part of that outcome: reserve them explicitly. Newly acquired file reservations extend the task file plan automatically, including discovered assembly references, so enabled Git publication includes them.
