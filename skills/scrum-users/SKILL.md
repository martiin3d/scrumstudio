---
name: scrum-users
description: Register human or agent identities and assign task owners in Scrum Studio, including claiming, renewing, and releasing work locks through its MCP.
---

Use the scrum-studio MCP. Local users are coordination profiles, not authenticated accounts.

- Register once with `user_register(identity, name, kind)`, where kind is `human` or `agent`. For an agent use a persistent unique logical identity such as `agent:<workspace>:<worker-id>` and a readable display name. Reuse that identity across reconnects of the same worker; distinct simultaneous workers need distinct identities. If no stable runtime ID exists, generate a UUID once and retain it for this session. Do not use a shared model name as the identity.
- Repeated registration returns the existing ID. Keep that numeric ID as `actor`; do not impersonate a human or another worker. Use `users` only when discovering existing profiles is necessary.
- For sequential work sessions, persist and reuse the logical worker identity/actor instead of generating a new chat identity each time. Every session must run [scrum-resume](../scrum-resume/SKILL.md) to review old own file reservations. Concurrent workers still require different identities.
- Assign without locking via `task_update(project,id,actor,owner_id)`; 0 unassigns. A visible owner records responsibility but does not reserve execution; an unlocked task can be claimed by another worker. Release an active lock before reassignment.
- Start work with `task_claim(project,id,actor)`. It atomically assigns the owner, acquires a lease, and moves In Progress. Save the returned `token` privately in session context. A suggestion from `next_work` is not a claim. On a conflict, get a different task; never proceed assuming the claim succeeded.
- When editing and starting together, `task_update(...,claim=true,actor,...fields)` performs both atomically and also returns a token. Human recovery after force-release can move a released In Progress task to TODO and reassign it. Comments by other registered users are allowed during your lock and do not renew it; work-log and task edits remain protected.
- Supply `actor` and `token` with edits to a locked task. Edits renew the lease to one hour. For long work without updates, renew before expiry with `task_claim` using the same actor and token; default lease is 3600 seconds, configurable 60..14400. No rapid polling or idle heartbeats. Pause task execution if renewal fails.
- Moving to TODO, Blocked, In Review, Done or Cancelled releases the lock and retains the owner. Explicit `task_release(project,id,actor,token)` preserves owner and status; expiry also makes the task reclaimable. Reclaim before editing a released/expired In Progress task. A new claim issues a fresh token; the former worker must stop. Cancelled needs a reason and must be reopened before claiming.
- A human can recover an abandoned lock with `task_release(...,force=true)`. An agent must not register as human or force another worker's lock; ask the human to coordinate recovery. Never put tokens in notes, descriptions, or user-facing reports.

Cancellation also removes the task from dependent blocker lists and returns fully unblocked Blocked tasks to TODO; it remains distinct from successful completion in metrics.

Use user_manage(actor=<active human>,id,action=delete|restore) only when the human asks to remove/restore a profile. This is installation-wide across registered projects. Agent deletion recovers unfinished task ownership and all its file/task reservations. Actionable work returns to TODO; genuine blockers and In Review evidence remain. Done/Cancelled records and original authorship are preserved. Managed active workers receive individual Stop first: pending=true means wait for exit and retry deletion; it does not mean deletion succeeded. Active unmanaged workers require explicit closure. Unavailable folders prevent recovery; restore access and retry. Partial recovery is reported and retries do not duplicate completed recovery activity. Human profiles retain live-work guards and the last active human is protected. Deleted identities cannot act, reclaim work, start managed profiles or silently re-register; a human must restore them. No provider account is deleted. Web Users hides deleted profiles by default and offers Show deleted profiles / Restore.
