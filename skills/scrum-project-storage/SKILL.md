---
name: scrum-project-storage
description: Open, export, restore, migrate or forget folder-scoped Scrum Studio projects through MCP, preserving Git snapshots and keeping local sessions and file locks isolated.
---

Use `projects` once to find the intended folder/checkout. Project UUID is portable; numeric project IDs, actor IDs, database row IDs and checkout UUIDs are local. Distinct clones may share project UUID and name, so match the absolute folder, not only name. After import/restore resolve tasks by project-scoped code; do not reuse cached numeric task IDs, note IDs, chat/activity cursors or claim tokens.

Task reference metadata survives export/import and normal task changes; attachment file bytes are not embedded in snapshot.json. project_export reports attachment count and this limitation when references exist. For an authorized full transfer, copy .scrum/local/attachments separately into the destination checkout's local attachment storage; do not publish blobs implicitly or add them to this application repository's ignored board. task_attachment list/get reports availability and missing content explicitly. Content retrieval is always opt-in (get include_content=true); routine task context remains metadata only.

- Create with `project_create(name,path,description?)` in an existing absolute directory. This writes .scrum metadata, not source scaffolding. Open/import an existing folder with `project_open(path)`. Opening preserves a nonempty local database; a Git snapshot imports only if no local project exists.
- Export with `project_export(project)` when requested or before an authorized Git handoff. It writes deterministic .scrum/project.json and snapshot.json, returning only counts/path. Keep .scrum/.gitignore and these JSON files in Git; never stage .scrum/local, registry databases or migration backups. Snapshots preserve user-written text, so review content before publishing. Exports do not push to Git.
- After Git changes to snapshot.json, `project_restore(project,confirm=true)` explicitly replaces local work and creates a local backup. Only do this when the human requested restoration/replacement; exporting first may overwrite the incoming snapshot. Release only your own unneeded claims; other active claims block restore. Resolve JSON conflicts before restore; invalid relationships, duplicate codes and cycles are rejected. There is no automatic merge.
- `project_forget(project)` removes the local panel entry without deleting files. Reopen its folder later; numeric registry ID may change. Release live work first. Missing folders can also be forgotten.
- `project_migrate(project,path)` copies one old shared-db project, preserves its IDs/history and local leases, and saves an original DB backup. Stop other old website/MCP processes first to prevent divergent writes; restart them afterwards. Migrate remaining legacy entries shown in Project folders. Never edit coordination databases directly.

Each checkout has ignored local scrum.db, locks.db and checkout identity. File conflicts are checked only within that checkout, even if another project targets the same physical file. Prefer independent source folders/checkouts. Git carries durable records, not live claims, locks or sessions; clones on different computers do not coordinate in real time. The web and MCP share a local registry and work independently. Use compact lifecycle tool results; do not load the exported snapshot into model context for routine work.

Human-authorized worktree retirement: project_workspaces(project,actor) previews only managed checkouts. confirm=true requires project Stop and no live claims; it moves all contents, including ignored and untracked files, into .scrum/local/worktree-archives, detaches only the validated managed checkout through Git, preserves branch refs, and records task continuity. It never merges changes or removes the canonical project. Reconcile committed branches and needed archived files before resuming workers, then change git_mode through project_settings. Failed detach restores moved files when possible and leaves a manifest for recovery; do not force deletion or edit registry databases.
